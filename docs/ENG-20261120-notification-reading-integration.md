# ENG-20261120 — Real notification and reading integration

State: IMPLEMENTED_LOCALLY

## Scope

- Run the backend quality gate inside the Java 21 Docker build target.
- Provide an isolated MySQL 8.4, Redis, RabbitMQ and Mailpit Compose stack.
- Seed only disposable accounts and a followed category, then publish through
  the real HTTP API so category notifications are generated by the business
  event path.
- Verify notification persistence, canonical reader destinations, reading-list
  state and reading history on MySQL.
- Exercise terminal delivery retention with retry-audit foreign keys enforced.
- Rehearse Flyway history validation against a caller-provided restored dump
  without running `repair` or changing production.

## Commands

```bash
docker build --target test -t nexus-api:test .
./scripts/run-docker-quality.sh
./scripts/run-notification-reading-e2e.sh
MYSQL_DUMP=/protected/isolated-restore.sql ./scripts/rehearse-flyway-history.sh
```

The notification journey script deletes its disposable Compose project on exit.
The Flyway rehearsal requires an explicitly supplied dump and uses a temporary
Docker network; it never connects to a production host unless the caller
explicitly points it there, which is prohibited by the release runbook.

## Release boundary

The production V181/V182 history mismatch still requires an approved backup,
isolated restore and before/after history review. No production `repair`, data
cleanup or migration is part of this change.
